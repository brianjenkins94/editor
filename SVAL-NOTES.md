# sval internals — field notes

Concrete architecture of sval as read from source. All line numbers are **sval v0.6.12, commit
`58550fd`** (re-clone `https://github.com/Siubaak/sval` if the tree is gone). MIT licensed.

> **Role under the committed design (see ASSIGNMENT §2):** tsval is Path B (tsc `SyntaxKind`) +
> stack-based, so sval's ESTree handlers and its generator/trampoline machinery are **reference only**
> — read them to learn *what each JS construct must do*, then re-express it in the stack VM. The parts
> that carry over as **code** are `Scope`/`Var`/`Prop` and the injection/sandbox concept. The
> "stepping edit points" and generator/trampoline sections below describe *how sval works*, not the
> tsval plan (tsval's stepping falls out of the VM loop, ASSIGNMENT §3).

## The evaluator is generator-based (the crux)

`evaluate/index.ts:15`:
```ts
export default function* evaluate(node, scope) {
  ...
  const handler = evaluateOps[node.type]
  if (handler) return yield* handler(node, scope)
  else throw new Error(`${node.type} isn't implemented`)
}
```
Every handler is a `function*`; the whole evaluation is one delegated generator tree. This is the
suspension substrate.

## Control flow = sentinels, not exceptions

`share/const.ts:3-9`:
```ts
export const AWAIT   = { RES: undefined }
export const RETURN  = { RES: undefined }
export const CONTINUE = { LABEL: undefined }
export const BREAK    = { LABEL: undefined }
```
Handlers set `.RES`/`.LABEL` and `return` the sentinel; parents test identity. Example
`statement.ts:60`:
```ts
export function* ReturnStatement(node, scope) {
  RETURN.RES = node.argument ? (yield* evaluate(node.argument, scope)) : undefined
  return RETURN
}
```
Note sentinels are **shared mutable singletons** (single-threaded assumption). `BlockStatement`
propagates them (`statement.ts:37-49`):
```ts
for (let i = 0; i < block.body.length; i++) {
  const result = yield* evaluate(block.body[i], subScope)   // <-- STEP-yield goes here
  if (result === BREAK) { ...; return result }
  if (result === CONTINUE || result === RETURN) return result
}
```

## Async = the runAsync trampoline + AWAIT sentinel (template for the step driver)

`share/async.ts:10`: `runAsync(iterator)` loops calling `iterator.next(res)`; when the yielded value
is the `AWAIT` sentinel it resolves the awaited promise and resumes; uses `iterator.throw`/`.return`
for error/early-return. **To add stepping: introduce a `STEP` sentinel, `yield` it at statement
boundaries, and extend this loop to *pause* (hand control out) on `STEP` instead of continuing.**
`index.ts:120 run()` chooses the async (generator) path only for `module` + ecmaVer≥13; otherwise it
uses the sync `evaluate_n`. For tsval, always use the generator path.

## Function creation — the perf fork to remove

`evaluate/helper.ts:132 createFunc`:
```ts
if (!node.generator && !node.async) {
  return createAnotherFunc(node, scope, options)   // <-- delegates to evaluate_n (SYNC) — DROP THIS
}
...
const tmpFunc = function* (...args) {   // generator path (currently only async/generator fns)
  const subScope = new Scope(scope, true)
  ... bind this/arguments/new.target/super, params ...
  yield* hoist(node.body, subScope)
  result = yield* BlockStatement(node.body, subScope, { invasived: true, hoisted: true })
  if (result === RETURN) return result.RES
  ...
}
```
Removing the line-137 fast-path makes **every** function a generator → the whole program is one
suspendable tree → uniform stepping across call boundaries. (Async/async-generator wrapping lives in
the `/*<remove>*/` block at `helper.ts:199-230`.)

## Scope (reuse wholesale) — `scope/index.ts`

- `new Scope(parent, isolated)` — `isolated=true` for function scope, `false` for block.
- `find(name)` walks parent chain, then `with` context, then falls back to
  `global().find('window').get()[name]` as a `Prop` — **this window fallback is the capability seam.**
- `var` hoists to nearest function scope; `let`/`const` respect TDZ (`DEADZONE`).
Complete and correct — supersedes DumbLang's scope.

## Injection / sandbox seam — `index.ts`

- Constructor (`index.ts:70-84`): `sandBox: true` → `createSandBox()` shallow-clones globals into a
  `win` bound as `globalThis`/`window`/`self`. `false` → real `globalObj`.
- `import(name, mod)` (`index.ts:93`) → `scope.var(name, mod)`. **This is where you inject recording /
  deny-by-default capability shims** (`fetch`, `fs`, `child_process`, env accessors).
- `run(code | Node)` and `parse(code, parser?)` (`index.ts:109,120`) accept a **pre-built AST Node**
  and a **custom parser** → the TS front-end hook (feed oxc's TS→ESTree AST).

## Stepping edit points (S2 summary)

1. `share/const.ts`: add `STEP`.
2. `evaluate/statement.ts`: `yield STEP` around each statement in the statement-list loops
   (`BlockStatement:38`, `Program`, loop bodies, `SwitchCase` consequents).
3. `share/async.ts`: extend the trampoline to pause on `STEP`; expose `step()/resume()/runUntil()`.
4. Track `node.start/end` for breakpoints/highlighting (acorn & oxc nodes both carry them).
5. `evaluate/helper.ts:137`: remove the `_n` fast-path so stepping crosses into called functions.

## Gotchas

- Shared-singleton sentinels: fine single-threaded; be careful if you ever interleave two runs.
- `evaluate_n` references in `index.ts:9,11` and `helper.ts:5,131` will dangle once you delete the
  twin — repoint them to `evaluate/` (that's exactly what the `<replace>` markers encode).
- oxc TS AST has TS-only node types; the interpreter must skip (erase) or implement them. The ones
  needing real runtime emit: `enum`, `namespace`/module, parameter properties, decorators, `import =`.
- Generators can't be cloned → no snapshot/fork without the stack-IR or replay approach (ASSIGNMENT §5 S4).
